**Weather Chat Agent**

一个基于 LangChain 1.0 和 DeepSeek 的对话机器人，支持多轮记忆、工具调用和真实天气查询。



**项目简介**

这个项目是一个可交互的命令行对话 Agent。用户可以用自然语言连续对话，当询问天气时，Agent 会自动调用 Open-Meteo 的免费天气 API 获取真实数据，而不是依赖预设的假数据。项目的主要目的是练习 Agent 开发的核心链路：模型配置、工具定义、工具调用循环、对话记忆和异常处理。



**功能**

多轮对话记忆，同一会话内记住上下文。天气查询工具，接入 Open-Meteo 真实 API。支持北京、上海、广州三个城市。天气代码到中文描述的映射，基于 WMO 标准。HTTP 错误和网络超时的异常处理，工具失败时模型如实告知用户，不编造数据。



**技术栈**

Python 3.10+，LangChain 1.0（create\_agent），LangGraph（InMemorySaver 记忆存储），DeepSeek API（deepseek-flash 模型），Open-Meteo API（免费天气数据，无需 Key），requests。



**快速开始**

第一步，安装依赖。在终端运行 pip install langchain langchain-deepseek langgraph requests。



第二步，配置 API Key。在项目根目录创建 .env 文件，写入 DEEPSEEK\_API\_KEY=你的密钥。或者直接在终端设置环境变量 export DEEPSEEK\_API\_KEY=你的密钥。代码通过 os.environ\["DEEPSEEK\_API\_KEY"] 读取，不会把密钥写死在源码里。



第三步，运行。在终端执行 python main.py，输入问题开始对话，输入 quit 退出。



**使用示例**

用户输入“北京天气怎么样”，助手返回北京当前天气为晴，气温 18°C，风速 12 km/h。用户输入“上海呢”，助手返回上海当前天气为多云，气温 22°C，风速 9 km/h。用户输入“深圳天气怎么样”，助手返回抱歉，目前暂未收录深圳的天气信息，仅支持查询北京、上海、广州。



**设计决策**

为什么用 create\_agent 而不是手写循环？LangChain 1.0 的 create\_agent 把“模型思考、判断是否调工具、执行工具、再生成回复”这套循环封装好了，底层跑在 LangGraph 上。手写循环适合理解原理，但工程上重复造轮子没有意义。



为什么用 InMemorySaver？当前版本用内存存储对话历史，程序关闭后历史丢失。这是本地测试阶段的合理选择。生产环境应换成 SqliteSaver 或 PostgresSaver 实现持久化。



为什么天气代码要单独做映射表？Open-Meteo 返回的 weathercode 是 WMO 标准的数字代码，比如 0 代表晴、61 代表小雨，不能直接展示给用户。WEATHER\_CODE\_MAP 把代码翻译成中文描述，未知代码有兜底文案，不会因为 KeyError 崩溃。



为什么只支持三个城市？Open-Meteo 的免费接口按经纬度查询，不直接识别城市名。CITY\_COORDS 手动维护了三个城市的坐标。这是一个明确的设计边界，不是 bug。扩展城市只需在字典里加一行经纬度。



**测试记录**

手动测试了五类场景，验证工具链路的可靠性。正常查询北京天气，返回了真实气温、风速和天气描述。多轮记忆测试先问北京再问“上海呢”，能正确理解指代并返回上海天气。不支持城市测试：输入深圳天气，模型如实告知暂不支持并列出支持城市，没有编造数据。HTTP 错误测试故意把 URL 写错，模型返回 404 详情并指出 URL 路径错误，没有编造天气。超时测试把 timeout 设为 0.001，模型如实报告超时、给出替代方案，没有编造天气。其中 HTTP 错误和超时场景下，模型均明确表示不会凭空编造天气数据，验证了工具错误信息粒度足够让模型做出合理判断。



**已知问题与下一步**

记忆不持久化，当前用 InMemorySaver，程序重启后对话历史丢失，下一步计划换成 SqliteSaver。城市覆盖有限，仅支持三个城市，扩展需要手动加坐标。未做自动化测试，当前为手动测试记录，后续考虑用 pytest 覆盖正常查询和异常路径。天气数据源单一，依赖 Open-Meteo 的可用性，后续可考虑加本地缓存或降级数据源。



**项目结构**

根目录下 Weather\_Chat\_Agent.py 是主程序，包含模型配置、工具定义、Agent 创建和对话循环。README.md 是项目说明。.env 存放本地环境变量，不提交到 Git。



**关于**

这是一个用于学习 Agent 开发的练手项目，重点在于理解工具调用循环、对话记忆管理和异常处理，而不是追求功能数量。
